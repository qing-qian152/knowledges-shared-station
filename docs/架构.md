# 架构

这份文档讲「东西放在哪、为什么这么放、改的时候会牵连到谁」。
想知道某一段内容该写多少字，看 [内容规范.md](内容规范.md)；想部署或排查线上问题，看 [部署.md](部署.md)。

---

## 为什么不把站点塞进子目录

仓库里有两个项目，看起来最"整齐"的排法是：

```
daily-learn/    ← 每天那个站
time-ledger/    ← 时间账本
```

**不能这么改**，除非同时改部署方式。现在 GitHub Pages 的来源是
`Deploy from a branch` → `main` / `/ (root)`，也就是**仓库根目录直接就是网站根目录**。
`index.html`、`assets/`、`data/`、`sw.js`、`manifest.json` 一旦下移一层：

- 线上 `https://<user>.github.io/<repo>/` 会变成 404 或目录列表
- 已经分享出去的 `?d=2026-11-22` 深链全部失效
- `sw.js` 里 `scope` 与 `SHELL` 相对路径全部错位，老访客会卡在旧缓存

真要分目录，得先把 Pages 改成 `GitHub Actions` 发布（用 artifact 上传 `daily-learn/`），
再加一条 301/跳转。这是个独立任务，不是"整理文件"能顺手做完的。
所以现在的分工是：**根目录 = 站点，子目录 = 另一个项目**，并在 README 里写清楚。

## 目录结构

```
.
├── index.html                 页面骨架（顶栏 / 板块标签 / noscript 往期链接）
├── sw.js                      Service Worker（缓存策略）
├── manifest.json              PWA 清单（图标、名称、主题色）
├── robots.txt / sitemap.xml   脚本生成，别手改
├── .nojekyll                  让 Pages 跳过 Jekyll 处理
├── AGENTS.md                  给写内容的 agent 看的契约
├── assets/
│   ├── style.css              设计系统（6 套配色 + 字体 + 字号 + 纸感布局）
│   ├── app.js                 全部渲染与交互（1780 行，见文末「已知取舍」）
│   ├── art.js                 21 幅程序化水墨插画（无外部图片）
│   ├── pwa.js                 SW 注册 + 安装引导
│   └── fonts/                 四份中文字体子集（思源宋 / 文楷 / 文鼎楷 / 朱雀仿宋）
├── data/days/
│   ├── index.js               日期索引 window.LEARN_INDEX，脚本维护
│   └── YYYY-MM-DD.js          一期内容 window.LEARN_DAY
├── scripts/
│   ├── daytool.py             唯一的内容工具：new / build / check / publish / site
│   ├── check-structure.mjs    结构体检（清单漂移）
│   ├── check-themes.mjs       外观体检（变量齐全）
│   └── dev-server.mjs         本地静态预览
├── docs/                      本目录
├── time-ledger/               时迹（独立项目，互不依赖）
└── .github/workflows/
    └── verify.yml             每次 push 校验，不写文件
```

**哪些文件是生成物**（改了会被覆盖，别手改）：

| 文件 | 由谁生成 | 触发时机 |
| --- | --- | --- |
| `data/days/index.js` | `daytool.py update_index()` | `build` / `publish` / `check --fix` / `site` |
| `sitemap.xml`、`robots.txt` | `daytool.py refresh_site()` | `publish` / `site` |
| `index.html` 里 `<!--ARCHIVE:START-->` 到 `<!--ARCHIVE:END-->` 之间 | 同上 | 同上 |

`verify.yml` 会重跑 `daytool.py site` 然后 `git diff --quiet`——生成物一旦落后于 `data/`，CI 直接红。

## 渲染链路

```
浏览器
  └─ index.html                       只有骨架，没有正文
      ├─ assets/art.js               定义 window.Art（21 个 SVG 场景）
      ├─ assets/app.js               读 window.LEARN_INDEX 建日期下拉
      │   ├─ <script src="data/days/YYYY-MM-DD.js">   动态插入，注入 window.LEARN_DAY
      │   └─ 用原生 DOM 拼出四个板块，写进 #main
      └─ assets/pwa.js               注册 Service Worker + 安装引导
```

几个刻意的选择：

- **数据是 `<script>` 不是 `fetch`**：`file://` 下 `fetch` 会被 CORS 拦，而"双击就能看"是这个站的第一需求。
- **不用框架**：`app.js` 自带 `h(tag, attrs, ...children)` 之类的十几行工具函数，够用了。
- **`?d=` 是唯一的状态源**：切日期只改 URL（`history.pushState`），刷新、分享、收藏都能还原。

## 数据模型

`data/days/YYYY-MM-DD.js` 是一段脚本，内容是纯 JSON：

```js
window.LEARN_DAY = {
  date, weekday, theme,
  quote: { text, author, source },
  chinese:  { title, author, origin?, tag, readingTime, image, imageCaption,
              body[], explain[], words[], expressions[], techniques[], imitation{} },
  poem:     { title, author, dynasty, tag, image, imageCaption,
              body[], notes[], translation, appreciation[], recite },
  english:  { title, level, words, body[], translation[], vocab[], collocations[],
              phrases[], patterns[], grammar[], summary, questions[], output{} },
  listening:{ title, level, words, topic, lines[{ en, cn }], note },
  checklist:[{ text, tip }]
};
```

- `questions[].answer` 是 **0 起始下标**（0 = A）。
- `chinese.origin` 只有两个合法值：`"public"`（逐字照录公版原文，可署真名）与 `"original"` / 缺省（本站原创，署「本站原创」）。校验器靠它区分"照录经典"和"给原创文字署名家属伪造"。
- `image` 只认 `art.js` 里存在的场景名，写错会静默退回素纸 `paper`（校验器会先拦一次）。

## 缓存策略

`sw.js` 分两个缓存桶，随 `VERSION` 常量整体换代：

| 资源 | 策略 | 理由 |
| --- | --- | --- |
| `data/**`（每日内容） | 网络优先，失败回落缓存 | 每天都要最新的，断网时退回上次读过的 |
| 其余外壳（html/css/js/图标/manifest） | 缓存优先 + 后台更新 | 打开要快；新版本下一次访问生效 |

> ⚠️ **改了外壳文件（`assets/`、`index.html`、`sw.js`、`manifest.json`）就必须把 `sw.js` 的
> `VERSION` 加一**（现在是 `v12`）。否则老访客永远拿到旧缓存，而且没有任何报错提示。

## 外观系统

面板（右上角 ◐）只做一件事：把选择写到 `<html>` 的
`data-theme / data-zh / data-en / data-size` 上，CSS 用属性选择器换变量。

变量分四类，`scripts/check-themes.mjs` 按**值长什么样**自动归类，不靠硬编码名单：

| 类别 | 前缀/形态 | 该在哪定义 |
| --- | --- | --- |
| 配色 | `--bg` `--ink` `--accent` …（值是 `#hex` / `rgb()`） | `:root` 定义一套默认，每套主题重定义全部 15 个 |
| 插图 | `--art-*`（9 个） | 每套主题各一套，换主题时插画跟着变色 |
| 字体 / 字号 | `--ff-*`、`--fs`（14 个） | **只在 `:root` 出现一次**，散到主题块里会让"换主题"顺手改掉字体 |
| 其它结构 | `--shadow`、`--topbar-h` … | 只在 `:root` |

**加一套主题**：`style.css` 里补 `:root[data-theme="xxx"]{ … }`（15 个配色 + 9 个 `--art-*` 齐全），
`app.js` 的 `THEMES` 加一项，然后 `node scripts/check-themes.mjs` 体检。

**加一款中文字体**：子集化 woff2 放进 `assets/fonts/`，`style.css` 加 `@font-face` 与
`:root[data-zh="xxx"]` 规则，`app.js` 的 `ZH_FONTS` 加一行。想让它在外观面板里有字形预览，
还要往 `YONG` 里补一条同名字形的 path——面板里的"永"字是**内联 SVG 轮廓**（约 4.5 KB），
不是真套 `font-family`，否则一打开面板就会把四套 CJK 字体全下下来（约 6.5 MB）。

字体策略：**宋体走系统优先**（iOS/macOS 自带，一个字节都不用下），
楷书 / 文楷 / 仿宋仍 webfont 优先（这三款只有靠自带字体才看得出差别，且是用户主动选的）。

## 插图

`assets/art.js` 里 21 个场景，全部是代码画的 SVG，不引用任何外部图片：

```
lotus-moon 荷塘月色   autumn-mountain 空山新雨   bamboo 竹林清影
snow-peak 雪岭        snow-boat 江雪孤舟          spring-river 春江
rain-window 雨窗      dunes 大漠孤烟              border 边塞烽烟
pastoral 田园         tower 登高                   plum 寒梅
autumn-river 秋江芦荻 pine-valley 松间清泉        lamp 灯下
paper 素纸(兜底)      desk 书桌                    bloom 花枝
orbit 星轨            signal 数据流                market 市况
```

- 同一个场景名同一天画出来一样，**换一天构图会重新随机**（seed 取日期），所以每天不重复。
- 数据里没写 `image` 时，`app.js` 的 `SECTION_ART` 按「日期 + 板块」稳定挑一张；
  兜底用的 `desk` / `bloom` 也在白名单里，可以直接写进数据。
- 场景名有两处清单：`art.js` 的 `SCENES` 与 `daytool.py` 的 `ART` 白名单。
  **两处必须同步**，`check-structure.mjs` 会交叉校验（曾经漂移过：`desk`/`bloom` 在画里能用、
  在数据里写不进去）。末尾三个 `orbit / signal / market` 是别的站点留下的，本站用不上，不算白名单成员。

## SEO

站点是纯前端渲染，服务端 HTML 里没有正文，历史日期原来也只能靠 `<select>` 切换。
为了让搜索引擎看到每一天：

- `daytool.py site` 从索引生成 `sitemap.xml`，并把往期写成 `index.html` 里 `<noscript>` 中的**真链接**。
- 页脚另有一份「往期」导航（`?d=日期` 形式），既是给读者的，也是给爬虫的。
- `app.js` 的 `syncMeta()` 按当天内容改写 `title / description / canonical / og / twitter`，并输出 JSON-LD。

⚠️ `<noscript>` 里的归档区由脚本写入，手改会被下次运行覆盖。

## 已知取舍

这些是知道但不打算现在改的，写在这里免得下次又"发现"一遍：

1. **`assets/app.js` 1780 行单文件**。拆成模块就得用 `<script type="module">`，
   而 ES module 在 `file://` 下会被 CORS 拒绝——等于放弃"双击就能看"。
   如果哪天不做 `file://` 了，第一件事就是按 `render/`、`look/`、`store/`、`export/` 拆开。
2. **字体 7.4 MB 进 git**。它们只会被主动选中的用户下载（且宋体默认走系统字体），
   但仓库体积确实因此变大。真要优化，得改成构建期从 CDN 子集化，与"零构建"冲突。
3. **内容文件注入 `window.LEARN_DAY` 而不是 JSON**，理由同上（`file://`）。
4. **生成物（sitemap / 索引 / 归档区）入库**。静态托管没有构建步骤，只能入库；
   代价是"源码"和"产物"混在同一个目录，靠 `verify.yml` 的 diff 检查兜底。
5. **`time-ledger/` 是仓库里的第二个项目**，与站点无耦合，但共用同一个 `LICENSE`（代码 MIT）。
